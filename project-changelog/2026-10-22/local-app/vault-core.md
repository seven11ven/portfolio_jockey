## Decisions made during this phase
- **Own libsodium bindings, no new packages.**
  - `sodium_libs`, the library the original plan named, is discontinued.
  - Its successor `sodium` would add 12+ dependencies to code-review, plus a build hook that compiles a bundled libsodium on every build.
  - The project manager chose small bindings of our own instead, through Dart's built-in `dart:ffi`, with the system's libsodium. `pubspec.lock` is unchanged.
- **Argon2id at libsodium's MODERATE preset** (3 passes, 256 MiB), chosen by the project manager. The settings are stored in the vault file, so they can be raised later without breaking existing vaults.
- **Platform reach:** asked by the project manager, and recorded in the new `public-notes/linux-support.md`. The app targets any 64-bit Linux desktop with Flatpak (x64 now, arm64 to be decided in phase 8). It was checked against Flutter's supported-platforms page and Flathub's per-distribution setup pages.

## Change
- **`public-notes/linux-support.md` (new):** the major distributions (whether Flatpak is built in or needs installing), the requirements, and what isn't supported.
- **`.devcontainer/setup.sh`:** installs `libsodium23` (Debian 1.0.18-1+deb12u1). It was also installed in this container.
- **`app/lib/vault/` (new):**
  - `native/sodium.dart`, `native/libc.dart`: the only files that load native libraries. libsodium is found as `libsodium.so.26` (1.0.19+) or `libsodium.so.23` (1.0.18) and must be at least 1.0.18. Every size is read from libsodium.
  - `secure_buffer.dart`: keys and the passphrase live in libsodium's guarded memory. It's locked except while in use, and wiped when freed.
  - `kdf.dart`: Argon2id on a background isolate, so the interface never freezes. Settings above 10 passes or 2 GiB are refused before any work is done.
  - `vault_header.dart`, `vault.dart`: the 112-byte `.pj/vault` file, `Vault.create`, `unlock` and `changePassphrase` (which re-wraps the master key only), and `UnlockedVault` with `lock()` and project index access.
  - `project_index.dart`: the encrypted project index. The project ID is authenticated, so indexes can't be swapped between projects.
  - `blob_stream.dart`: streamed file encryption with libsodium secretstream, 64 KiB chunks and a key per file. It detects changed, reordered, dropped or extra chunks, and a file cut short.
  - `atomic_write.dart`: temporary file, flush, rename, then sync the folder.
  - `ids.dart`, `layout.dart`, `errors.dart`, `aead.dart`.
  - **No UI.** None of these ask for confirmation; phase 5's screens show the confirm/cancel step before calling anything that writes.
- **`app/test/vault/` (new):** 54 tests. `known_answers.dart` was generated by script from libsodium's own test files.
- **`app/tool/check-privacy.sh`:** new check 6. Only files listed in **`app/tool/allowed-native-libs.txt` (new)** may open native libraries, using plain-string names and only the listed functions. libc is limited to `malloc`, `free`, `open`, `fsync` and `close`, so its network functions can't be bound.
- **`docs/dependencies.md`:** new "Native libraries" (libsodium review, libc) and "Vault format" sections.
- **`CLAUDE.md`:** project state, the libsodium requirement, and the new rules.

## libsodium review (new guideline: examine the code)
- **Signature:** the official 1.0.18 tarball passed its minisign check. The signing key was confirmed on two separately hosted official sources. SHA-256: `6f504490…636c1`.
- **Source:** the C source was grepped and every hit read. There is no network, process, environment or logging code. Its only file access reads `/dev/random` and `/dev/urandom` for randomness.
- **Binary:** Debian's installed binary imports only basic libc functions and nothing for networking.
- **Debian's patch:** it fixes CVE-2025-69277 (elliptic-curve point checks), which the vault doesn't use.
- **License:** ISC. In plain words: free to use, change and share, keeping the notice. No warranty.
- **Cleanup:** `minisign` was installed temporarily and then removed, and the downloaded files were deleted.

## Verification
- `flutter analyze --fatal-infos --fatal-warnings`: no issues.
- `flutter test`: all 55 tests pass, including the 54 vault tests:
  - **Known answers:** the XChaCha20-Poly1305 ciphertext and Argon2id vectors 0 and 4 match libsodium's own test results exactly, and vector 3 is refused as libsodium's suite expects.
  - **Round trips:** empty, 1 byte, chunk boundaries and 5 MB.
  - **Integrity:** a wrong passphrase, every part of the vault header changed, out-of-range settings, flipped bits, cut files (at and inside a chunk), swapped chunks, extra data, a wrong key, a changed chunk size, indexes swapped between projects and between vaults, and IDs that try to escape the storage folder.
  - **Atomic writes:** failures leave the original file and no temporary file behind.
  - **Keys:** a disposed key can't be used again.
- **Unlock at MODERATE:** 459–521 ms on this 2-core cloud machine (3 runs). Argon2id uses its fixed 256 MiB while it runs.
- **`check-privacy.sh` passes.** On throwaway copies, check 6 failed as intended for:
  - opening libcurl from a new file, or from the libsodium bindings
  - binding libc's `socket`
  - a library or function name that isn't a plain string
  - `DynamicLibrary.process()`

  That testing found a bug in check 6 itself, which was fixed: it read single files without their names and so saw almost no code.
- `check-lockdown.sh` passes. No servers, ports or test files were left behind.

## Known limits (documented in `docs/dependencies.md`)
- The typed passphrase exists briefly as a Dart string, which can't be wiped.
- An open project's decrypted names and per-file keys are in Dart's normal memory. The master key never is.
- File decryption streams, so callers must discard everything from a stream that ends in an error (this matters for preview and "Edit in…" in phase 6).
