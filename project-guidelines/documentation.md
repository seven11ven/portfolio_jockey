# Documentation Guideline for features and programming in this Project
There are two prime set of rules that make up this guideline


## Programming
* Assume the User is unfamiliar with the coding language. A markdown file under "/project-notes/documents/programming_documentation.md"
    - This should outline how the code within the repo works. The purpose of whatever webhooks, API Keys, Secrets, etc were introduced and used in the project.
    - Keep it plain and simple. Have it so the User understands how the programming works, why the language was used. So if a AI-Agent were ever down, the User could still complete their work despite the hinderance.

## Features
* Always keep a record of the features in the project in a markdown file under "/project-notes/documents/feature_documentation.md" This makes it easier to track and list project specifications wherever legal or consumer presenting circumstances arise.
